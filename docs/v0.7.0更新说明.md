# v0.7.0 更新说明

> 2026-11-24。用户指出两个问题：管理员不该有「我的申请」；审批应该让用户真的上传文件、管理员审核后能真正导入。本轮补完整。

## 一、修正管理员菜单逻辑

v0.6.0 里管理员菜单同时有「数据导入」「我的申请」「导入审批」，其中「我的申请」是逻辑瑕疵——管理员自己就能导入，不需要申请。

- `App.vue` 菜单项 `requests` 标记 `userOnly: true`，`visibleMenu` 按 `adminOnly / userOnly` 双重过滤。
- 现在管理员看到 7 项（无「我的申请」），普通用户看到 6 项（无「数据导入」「导入审批」）。

## 二、审批闭环补完整：真实文件上传 + 审核 + 导入

v0.6.0 的申请只登记文件名和用途，不传文件、也不能真正导入。本轮补全。

### 流程

1. 普通用户在「我的申请」选择 Excel/CSV 文件、填目标表和用途 → 提交。
2. 后端把文件保存到 `data/import_uploads/`，数据库记录 `file_path`，状态 `pending`。
3. 管理员侧栏「导入审批」出现红色角标；点开可看到申请人、文件、用途。
4. 管理员点「预览文件内容」→ 后端解析文件返回行数、字段、前 5 行，管理员据此判断。
5. 管理员「批准」（可填意见）或「驳回」。
6. 批准后，在「已处理记录」里点「执行导入」→ 后端读申请文件、INSERT 到目标表、状态变 `imported`、记录导入行数。
7. 普通用户在「我的申请」看到状态 `imported` 和导入行数。

### 状态机

`pending`（待审批）→ `approved`（已批准）/ `rejected`（已驳回）→ `imported`（已导入）

重复审批会被拒绝；只有 `approved` 状态能执行导入；导入只能执行一次（导入后状态变 `imported`）。

### 代码改动

| 文件 | 变化 |
|---|---|

| `.gitignore` | 排除 `data/import_uploads/`，避免上传文件被提交 |

### 修了一个 bug

`get_request()` 原来用 `dict(zip(keys, row))` 按位置映射，但 ALTER TABLE 加列后实际列顺序与硬编码的 keys 不一致，导致 `file_path` 取到 `.`、预览报 `PermissionError`。改用 `sqlite3.Row` 按列名取值，彻底避免顺序依赖。

## 四、论文里怎么写

第 3 章「需求分析与总体设计」可加一张角色权限矩阵 + 一张导入审批流程图；第 4 章「详细实现」写申请文件的存储、预览解析、批准导入三步。答辩边界：这是功能级工作流演示，不是 OA 引擎；文件存本地目录，不是对象存储。

## 五、已知取舍

- 上传文件存本地 `data/import_uploads/`，没有病毒扫描、没有大小限制提示（前端只限制了格式）。论文里如实说明。
- 审批通过后仍需管理员手动点「执行导入」，而不是批准即自动导入——这是有意的两步确认，防止误操作；也便于管理员在预览后再看一眼。
