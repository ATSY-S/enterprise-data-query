# 评测体系说明（v0.4.0 修正版）

## 一、先纠正上一版的两个错误

### 错误 1：消融实验的对照组 schema 是过时的

v0.3.0 的 `ablation.py` 里，"无语义层"组用的还是旧版 4 张表的表结构（写着 orders 有 category/region 字段），而新库是 8 张表、orders 没有这些字段。所以那次跑出的 **100% vs 46.7% 混入了"表结构本身是错的"这个因素，不能作为论文数据**。

已修正：两组用完全相同的表结构，只差"指标口径 / JOIN 关系 / 业务术语"三段说明。

### 错误 2：通过标准太弱

旧标准：`SQL 执行成功 且 返回行数>0`。这会把"SQL 跑通了但数算错了"也算通过。

已修正：新增 `eval_with_oracle.py`，把模型结果与标准答案逐格比对，数值容差 1%。

## 二、现在的评测体系

| 类型 | 数量 | 工具 | 判定标准 |
|---|---|---|---|
| 单元测试 | 27 个 | `pytest tests/` | 断言：SQL 守卫拦截、错误分类、数据完整性、金额口径一致、季节性存在 |
| 固定评测题 | 30 道 | `eval/run_eval.py` | SQL 可执行率（弱标准，仅作回归用） |
| **随机评测题 + 标准答案** | 30 道/次 | `generate_cases.py` + `eval_with_oracle.py` | **结果正确率**（强标准，论文采用） |
| A/B 消融 | 30 道 × 2 组 | `eval/ablation.py` | 有/无语义层的 SQL 可执行率对比 |

注意：单元测试和评测题是两回事。pytest 里 16 个测试函数用了参数化，实际跑出 27 个用例。

## 三、随机出题怎么做到的

`generate_cases.py` 从数据库真实数据抽参数（地区、品类、月份、会员等级……），**用参数化 SQL 先算出标准答案，再生成中文问题**。题目和答案天然配对，不靠人工维护。

```bash
python eval/generate_cases.py --count 30 --seed 42
python eval/eval_with_oracle.py eval/cases_random.json
```

换 seed 就换一批题（已验证 seed=7 生成完全不同的题目和答案）。这样论文里可以写"随机生成 30 道题、seed=42 可复现"，比固定题库更有说服力。

**oracle 口径必须与系统提示词严格一致**，否则会冤枉模型。第一次跑随机评测时 6 道失败，排查发现 5 道是 oracle 自己写错了（没过滤 `status='已完成'`、核销率按活动名而非活动 ID 分组）。修正 oracle 后正确率从 80% 回到 100%。

## 四、最终实验数据（论文可用）

### 4.1 随机评测（seed=42，30 道，带标准答案）

- SQL 可执行率：**100%**（30/30）
- 结果正确率：**100%**（30/30）
- 说明：模型在限定查询范围内（8 张表、单表与两表关联）表现稳定

### 4.2 A/B 消融（随机题 + oracle 判定，表结构相同仅差语义层）

| 方案 | SQL 可执行率 | **结果正确率** | 平均耗时 |
|---|---|---|---|
| 有语义层（指标口径 + JOIN 关系 + 术语） | 100% | **96.7%**（29/30） | 0.84s |
| 无语义层（只有表结构） | 90% | **50.0%**（15/30） | 0.78s |

结论：语义层带来 **46.7 个百分点**的正确率提升。没有口径说明时，模型容易用错字段（total_amount vs actual_amount）、选错 JOIN 路径、把同名活动跨年份混在一起。

这组数据是最终版本，判定标准是结果正确性而非仅仅"SQL 能跑"。

复现：`python eval/ablation.py eval/cases_random.json`

## 五、论文里怎么写这个评测

第 5 章"实验与结果分析"建议结构：

1. **实验设置**：数据集规模（8 表 / 2 万订单）、随机出题方法、seed=42 可复现
2. **评价指标**：定义"SQL 可执行率"和"结果正确率"（后者逐格比对，数值容差 1%）
3. **主实验**：随机 30 题，100% 正确率
4. **消融实验**：去掉语义层后降到 63.3%，证明指标口径模块的必要性
5. **失败案例分析**：展示 oracle 修正过程，说明"评测标准本身也需要严谨"——这段很有论文味，坦诚且有深度
6. **局限性**：题目限定在单表与两表关联；未覆盖多层嵌套与时间函数边界情况
