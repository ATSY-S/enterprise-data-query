# v0.6.0 更新说明

> 2026-11-23。本轮三件事：登录页动态背景、字段名中文化、角色权限差异化（含导入审批闭环）。

## 一、登录页动态背景

用户反馈原登录页背景太普通，参考 DeepSeek 的浅色微动态风格。

- 纯 CSS + Canvas 实现，不引第三方动画库。
- 三层效果：
  1. 浅蓝渐变底 + 淡入淡出的网格纹理；
  2. 三个模糊光斑（`blur(70px)`）以 18/22/26 秒周期缓慢漂移；
  3. Canvas 粒子层：约 80 个粒子缓慢漂浮、彼此靠近时连线，**鼠标 110px 范围内粒子被推开**，鼠标周围有径向光晕。
- 兼容 `prefers-reduced-motion`，系统开减少动画时光斑停止。
- 改动文件：`frontend/src/views/Login.vue`。

## 二、字段名统一中文

用户反馈图表里出现 `verify_rate`、`activity_name` 这类英文别名看不懂。

- 新增 `backend/labels.py`：`FIELD_LABELS` 字典覆盖 60+ 业务字段与常见 SQL 聚合别名（如 `verify_rate → 核销率`、`activity_name → 活动名称`、`sales_sum → 销售额合计`），并能解析 `SUM(actual_amount)` 这类表达式。
- `chart_service.py` 用统一的 `label_of()`：图表的系列名、X/Y 轴名全部中文。
- API 增加 `column_labels` 字段：`{"activity_name":"活动名称","verify_rate":"核销率"}`；前端 Chat.vue 表格表头用映射显示中文，数据行的 key 不变（避免破坏取值）。
- 一处定义，图表与表格共用；未知字段原样显示，不强行翻译。

## 三、角色权限差异化

用户的判断是对的——管理员和普通员工看到的东西必须不同。

### 权限矩阵

| 功能 | 管理员 admin | 普通用户 user |
|---|---|---|
| 数据概览 | 完整，含 8 张表的数据源规模 | 简化版：业务导览，不暴露表结构 |
| 智能查询 | 全部数据 | 全部数据（只读） |
| 数据导入 | 直接上传、预览、入库 | 无此菜单 |
| 我的申请 | — | 提交导入申请、跟踪状态 |
| 导入审批 | 待审批列表、批准/驳回、角标提示 | 无此菜单，接口 403 |
| 查询历史 | 全部用户 | 仅自己的 |
| 指标口径 / 系统说明 | 可见 | 可见 |

### 导入审批闭环（用户建议的方案，已实现）

普通用户提交申请（文件名 + 目标表 + 用途）→ 管理员在审批页看到待办（侧栏红色角标显示数量）→ 批准或驳回并可填意见 → 申请人在「我的申请」看到状态变化。每步留痕，重复审批会被拒绝。

- 新增 `backend/request_service.py`：`import_requests` 表（pending/approved/rejected 三态）、submit/list/review/pending_count。
- `api.py` 新增 `/api/requests`（提交与列表）、`/api/requests/pending-count`、`/api/requests/{id}/review`；申请必须登录，审批必须 admin。
- 前端新增 `ImportRequests.vue`（我的申请）、`Approvals.vue`（导入审批）；`App.vue` 菜单按角色过滤，审批页有待办角标。
- `Dashboard.vue` 按角色显示不同内容；`Login.vue` 演示账号说明同步更新。
- 安全：申请目标表也走白名单校验；普通用户调审批接口返回 403；重复审批返回明确错误。

## 五、论文里怎么写

- 第 3 章：补「角色权限设计」「数据导入审批流程」，可画权限矩阵表。
- 第 4 章：补「可视化渲染（ECharts）」「导入申请与审批模块」。
- 答辩边界照旧：权限是功能级隔离（不是 RBAC/行级列级），审批是轻量工作流（不是 OA 引擎），前端动效是纯 Canvas/CSS。

## 六、已知取舍

- Canvas 粒子每帧遍历点对，粒子数限制在 80，低端机可能有轻微开销；登录页停留时间短，影响可忽略。
- 审批通过后仍需管理员在数据导入页执行实际上传（申请阶段只登记元信息，不存文件）。这是有意的简化——把"文件传输 + 审批"全做进来会超出本科毕设边界，论文里如实说明即可。
