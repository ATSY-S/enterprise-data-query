# 功能调研与页面规划（v0.5 候选）

> 2026-11-21。对照腾讯 SuperSonic、DB-GPT、JimuReport/JimuChatBI、FastGPT、vue-vben-admin 五个项目，评估当前系统完成度，给出下一步取舍。

## 一、当前完成度自评

| 维度 | 现状 | 自评 | 说明 |
|---|---|---|---|
| 核心功能（NL→SQL→可视化） | 30 题正确率 100%，消融 96.7% vs 50% | 95% | 论文题目覆盖充分 |
| 后端工程结构 | 6 层拆分 + 27 个单元测试 | 85% | 本科毕设里算规范 |
| 数据规模与真实性 | 8 表、2 万订单、跨 2 年、有季节性 | 90% | 评测可信 |
| 容错与安全 | 错误分类、只读守卫、人工确认、兜底建议 | 85% | 有内容可写 |
| 前端页面 | 5 页（概览/查询/历史/指标/说明），两级响应式 | 65% | 缺身份与数据接入入口 |
| 身份与权限 | 无 | 0% | 唯一明显缺口 |
| 数据接入 | 无（只能靠建表脚本初始化） | 0% | 用户提的痛点 |

**一句话**：作为毕设，功能已经够了；作为"企业成品"，只差**身份**和**数据接入**这两块。

## 二、五个参考项目对照

| 项目 | 关键功能 | 可借鉴点 | 不建议照搬 |
|---|---|---|---|
| SuperSonic（腾讯音乐） | Chat BI + Headless BI 语义层；数据集/列/行三级权限；输入补全、多轮、查询后推荐 | 语义层思想（你已经做了）；三级权限说明企业确有必要 | Java 技术栈、复杂语义建模 |
| DB-GPT | 多源数据接入（数据库/CSV/Excel/文档）；Agent 编排；沙箱执行；报告生成 | 文件导入 → 入库这条路是主流 | Agent 自主规划、代码沙箱 |
| JimuReport / JimuChatBI | 数据源管理、表注册、语义建模、Chat2BI、AI 自动建表（默认关闭） | 表注册/数据源管理页面；`autoTableEnabled` 默认 false 的安全默认值 | 报表设计器、大屏 |
| FastGPT | 知识库、文档上传解析、团队权限、应用发布 | 团队/角色维度权限 | Next.js 技术栈、RAG 那套（跑题） |
| vue-vben-admin | Vue3 + Vite + TS + Monorepo；登录、路由守卫、表格表单、上传 | 登录页布局、路由守卫思路 | 整套框架（33.8k stars，太重） |

**共性结论**：成熟 ChatBI 产品的"三件套"是 **语义层 + 身份权限 + 数据接入**。你现在有语义层，缺另外两件。

## 三、要不要加登录权限

**建议：做，但只做轻量版。**

理由：
- 毕设答辩老师常问"不同用户权限怎么控制"，有登录能答；论文里也能写"身份认证与访问控制"一节。
- 但 SuperSonic 那套数据集/列/行三级权限，本科毕设做不完也不该做。

轻量版范围（约半天工作量）：
- 登录页：用户名 + 密码，bcrypt 校验
- 2 种角色：`admin`（可导入数据、看全部历史）/ `user`（只能查询、只看自己的历史）
- 后端：Token 校验中间件，`query/history` 按用户隔离
- 前端：路由守卫，未登录跳登录页

不做：注册、找回密码、OAuth、行级/列级权限、多租户。

## 四、要不要做"文档上传写进数据库"

**建议：做，但必须限定为结构化数据（Excel / CSV），不要碰 PDF/Word 向量化。**

这里有个关键边界要分清楚：

| 类型 | 例子 | 与你论文的关系 | 结论 |
|---|---|---|---|
| 结构化数据导入 | Excel/CSV → 追加到 orders 表或新建表 | 直接支撑"数据库自然语言查询"，新数据进来就能问 | **做** |
| 非结构化文档入库 | PDF/Word → 切片 → 向量库 → RAG | 那是你另一个项目（企业知识库）的方向，和本题偏离 | **不做** |

用户痛点（不会操作数据库）用结构化导入就能解决 90%：上传 Excel → 预览字段 → 确认入库 → 自动追加到语义层 → 立刻可以用中文查。

轻量版范围（约一天工作量）：
- 上传 `.csv` / `.xlsx`，后端用 pandas 解析
- 字段预览 + 目标表选择（追加现有表 / 新建表）
- 写入 SQLite，自动刷新语义层的表结构描述
- 导入历史留痕

安全默认值（照抄 JimuReport 的做法）：只允许 INSERT 到白名单表，不允许执行用户上传的 DDL/DML。

## 五、页面规划

现有 5 页保留，建议新增 2 页：

| 页面 | 作用 | 优先级 |
|---|---|---|
| 登录页 | 身份认证、角色区分 | 高 |
| 数据导入 | 上传 → 预览 → 入库三步向导 | 高 |
| 数据源管理 | 表清单、行数、字段说明、导入时间 | 中（可先并入概览页的一个区块） |

同时改造：
- 顶栏加当前用户 + 退出
- 历史页按当前用户过滤
- 概览页加"数据源"区块，展示 8 张表的规模和最近导入时间

**不建议**再加更多页面。页面越多，答辩时要讲的东西越多，反而分散题目重点。

## 六、前端参考材料

- **vue-vben-admin**（33.8k stars，Vue3 + Vite + TS）：只借鉴登录页布局、路由守卫写法，不引入框架。
- **JimuReport 数据源管理页**：借鉴"表选择 + 字段映射"的交互结构。
- **当前项目的 Element Plus 结构保持不变**，只加两个 vue 文件，不换 UI 库。

## 七、优先级建议

1. **先做数据导入**（和论文题目强相关，答辩能讲"系统支持动态数据接入"）
2. **再做轻量登录**（补齐企业完整性）
3. 数据源管理作为概览页区块，不做独立页
4. 全部完成后提交 v0.5.0，跑回归测试（27 单测 + 30 题评测）

## 八、论文角度的提醒

加这两个功能后，论文第 3 章"需求分析与总体设计"可以补两节：用户角色与权限、数据接入流程；第 4 章"详细实现"补数据导入模块；第 5 章评测不受影响。

**边界仍然要说清**：本系统不研究模型内部，权限只做功能级隔离（不是企业级 RBAC），数据导入只支持结构化表格（不支持文档语义解析）。这些写在"局限性与展望"，反而显得专业。
